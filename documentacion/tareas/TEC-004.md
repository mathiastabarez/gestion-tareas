# TEC-004 - Verificar y documentar la ejecución del proyecto

Estado: Pendiente

Fecha:

## Objetivo

Comprobar que el proyecto completo pueda configurarse y ejecutarse desde un clon limpio del repositorio, y documentar el procedimiento necesario para repetirlo.

## Tareas

- [ ] Confirmar que `TEC-001`, `TEC-002`, `TEC-003` y todas las historias de usuario estén completadas.
- [ ] Crear el `README.md` principal en la raíz del repositorio.
- [ ] Documentar en el `README.md`:
  - Objetivo y alcance breve del proyecto.
  - Estructura general de la solución.
  - Requisitos necesarios para ejecutarla.
  - Cómo clonar el repositorio.
  - Cómo restaurar dependencias y compilar la solución.
  - Cómo configurar `ConnectionStrings:GestionTareas` y `Api:BaseUrl` sin guardar secretos.
  - Cómo publicar el SQL Server Database Project.
  - Cómo iniciar la API y la Web.
  - Cómo ejecutar las pruebas unitarias.
- [ ] Realizar la comprobación desde un clon limpio o una copia limpia del repositorio.
- [ ] Restaurar dependencias y compilar todos los proyectos.
- [ ] Configurar los valores requeridos fuera del repositorio.
- [ ] Publicar la base `GestionTareas` desde el proyecto SQL.
- [ ] Ejecutar la API y comprobar que OpenAPI esté disponible.
- [ ] Ejecutar la Web y comprobar el flujo completo:
  - Crear una tarea.
  - Consultar la lista y el detalle.
  - Buscar por título o descripción.
  - Filtrar por estado.
  - Cambiar de página conservando los filtros.
  - Editar una tarea y cambiar su estado.
  - Eliminar una tarea con confirmación.
- [ ] Ejecutar todas las pruebas unitarias y comprobar que estén aprobadas.
- [ ] Comprobar que la Web muestre un mensaje comprensible cuando la API no esté disponible.
- [ ] Corregir la guía si algún paso requiere información adicional.
- [ ] Verificar que el repositorio no contenga credenciales, rutas locales, datos temporales cargados en la base ni archivos generados.

## Notas

La comprobación será manual y complementará las pruebas unitarias incluidas en cada historia.

La guía debe utilizar valores de ejemplo o marcadores, nunca credenciales ni rutas específicas del equipo.

No se documentará un despliegue en producción. Ese procedimiento se definirá cuando exista un entorno de destino.

Si la comprobación descubre una diferencia con `alcance.md` o `arquitectura.md`, esos documentos deberán corregirse antes de completar esta tarea.
