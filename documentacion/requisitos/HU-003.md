# HU-003 - Editar una tarea y cambiar su estado

Estado: Pendiente
Fecha:

## Historia

Como usuario,
quiero editar una tarea y cambiar su estado,
para mantener actualizada la información del trabajo.

## Criterios de aceptación

- [ ] La Web muestra el formulario con los datos actuales de la tarea.
- [ ] Se pueden modificar título, descripción, estado y fecha de vencimiento.
- [ ] Solo se aceptan los estados `Pendiente`, `EnCurso` y `Completada`.
- [ ] Se aplican las mismas validaciones y normalizaciones utilizadas al crear una tarea.
- [ ] El identificador y la fecha de creación no se modifican.
- [ ] Los datos inválidos no se guardan y la Web muestra los errores correspondientes.
- [ ] Editar una tarea inexistente produce una respuesta `404` y un mensaje comprensible.
- [ ] Después de guardar, la Web vuelve a la lista y muestra la información actualizada.

## Tareas

- [ ] Implementar en `Tarea` la actualización de sus campos editables.
- [ ] Crear `ActualizarTareaInput` y agregar el caso de uso a `ITareaService` y `TareaService`.
- [ ] Agregar a `ITareaRepository` la operación de actualización.
- [ ] Implementar el `UPDATE` parametrizado en `SqlTareaRepository`.
- [ ] Crear `ActualizarTareaRequest` y su mapeo a `ActualizarTareaInput`.
- [ ] Implementar `PUT /api/tareas/{id}`.
- [ ] Crear en la Web el modelo, mapeador, formulario y acciones de edición.
- [ ] Agregar al cliente HTTP la operación de actualización.
- [ ] Agregar pruebas unitarias para cambios válidos, datos inválidos, conservación de identificador y fecha, tarea inexistente y mapeadores.
- [ ] Comprobar manualmente la edición y cada cambio de estado.

## Notas

Depende de `HU-001` y `HU-002`.

No incluye eliminación.
